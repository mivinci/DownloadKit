WHY THIS MATTERS
═════════════════════════════════════════════════════════════════════════════

PERFORMANCE WIN
───────────────
Phase 1 (current):
  p.then(f).then(g).then(h).wait(scope)
  
  Allocates 4 heap objects:
  • ImmediatePromiseNode (existing)
  • TransformPromiseNode(f)
  • TransformPromiseNode(g)
  • TransformPromiseNode(h)
  + RootEvent on stack

Phase 2 (with coroutines):
  auto result = co_await Promise::resolve(initial)
    .then(f).then(g).then(h);
  
  Allocates 3 heap objects:
  • ImmediatePromiseNode
  • TransformPromiseNode(f)
  • TransformPromiseNode(g)
  (then chain stops; coroutine frame on stack replaces final step)

DEVELOPER EXPERIENCE WIN
────────────────────────
Sequential, readable async code:
  
  auto user = co_await fetch_user(id);
  auto posts = co_await fetch_posts(user.id);
  auto comments = co_await fetch_comments(posts[0].id);
  
Instead of nested callbacks:
  
  fetch_user(id, [](auto user) {
    fetch_posts(user.id, [](auto posts) {
      fetch_comments(posts[0].id, [](auto comments) {
        // ... nested callback hell
      });
    });
  });

TESTING & DEBUGGING
───────────────────
Coroutine frames appear on the stack, making debugging easier.
Exception handling with try/catch works naturally in coroutines.
