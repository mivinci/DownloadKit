**开发过程**：经历了多轮重构迭代：

1. 修复 `xAppend` 正确使用 len 字段
2. 重命名 `xAppendLength` → `xLen`

5. 移除 Header 中未使用的 `len`/`cap` 字段
6. **最终决策**（PR #5）：移除 `xAppend`/`xLen`，保持 malloc 模块为纯引用计数 API

## 经验总结

1. **API 设计迭代**：malloc 模块经历了"加功能→发现过度设计→精简"的过程，说明 API 设计应遵循最小化原则
2. **lazy thread creation**：按需创建线程比预创建更节省资源，但需要注意线程创建的开销
3. **idle timeout**：worker 退出时不能 `pthread_detach`，否则 `pthread_join` 会出错；需要在 join 时跳过已退出的线程
