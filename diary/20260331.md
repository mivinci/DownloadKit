### 6. CI/CD 搭建与 Linux 兼容性修复

**目标**：添加 GitHub Actions CI 工作流（PR #21）

**开发过程**：

1. 编写 `.github/workflows/ci.yml`（98 行）
2. 移除 CXX 的 `-Werror` 标志（测试文件使用 C++ 编译，warning 较多）
3. **Linux 死锁修复**：`stopped` 标志改用 atomic load/store，修复 epoll 下的死锁
4. **epoll wake pipe 修复**：改用 level-triggered 模式，修复 stop 竞态条件
5. **回退**：drain wake pipe 的 EPOLLET 边沿触发方案不稳定，回退到 main 版本

**问题排查**：

- **现象**：CI 在 Linux（epoll）上测试卡死
- **根因**：`stopped` 标志的读写没有内存屏障，导致 worker 线程看不到 stop 信号
- **修复**：使用 `xAtomicLoad`/`xAtomicStore` 保证可见性
- **二次问题**：wake pipe 在 edge-triggered 模式下可能丢失唤醒
- **最终方案**：回退到 level-triggered + 逐字节 drain

## 经验总结

1. **跨平台事件循环**：kqueue/epoll/poll 三种后端的 API 差异较大，需要良好的抽象层设计
2. **epoll edge-triggered 的坑**：ET 模式下必须一次性读完所有数据，否则会丢失事件；对于 wake pipe 这种场景，LT 模式更安全
3. **atomic 的重要性**：跨线程共享的标志位必须使用 atomic 操作，否则在弱内存序架构上会出现可见性问题
4. **CI 是最好的测试**：本地 macOS 跑通的代码在 Linux CI 上暴露了多个并发问题，说明跨平台 CI 的价值
