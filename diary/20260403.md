### xlog 异步日志模块 — 从零实现

按照需求文档和实施计划，完整实现了 `xlog` 异步日志模块（10 项任务全部完成）。

#### 实现内容

1. **目录结构与构建集成**
   - 创建 `xlog/` 目录，添加 `xlog/CMakeLists.txt`（GLOB_RECURSE + SHARED lib + GTest）
   - 根目录 `CMakeLists.txt` 添加 `add_subdirectory(xlog)`

2. **公共 API 设计** (`xlog/logger.h`)
   - `xLogLevel`（Debug/Info/Warn/Error/Fatal）、`xLogMode`（Timer/Notify/Mixed）枚举
   - `xLoggerConf` 配置结构体（loop、path、mode、level、max_size、max_files、flush_interval_ms）
   - 生命周期：`xLoggerCreate` / `xLoggerDestroy`
   - 核心函数：`xLoggerLog`、`xLoggerFlush`、`xLoggerCurrent`
   - 桥接：`xLoggerEnter` / `xLoggerLeave`
   - 便捷宏：`XLOG_DEBUG` / `XLOG_INFO` 等（自动使用线程局部 logger）+ `XLOG_*_L` 显式版本

3. **内部结构** (`xlog/logger_private.h`)
   - `xLogEntry_`：MPSC 节点 + 级别 + 格式化缓冲区
   - `xLogger_`：事件循环、文件句柄、MPSC 队列、pipe fd 对、定时器、轮转字段

4. **完整实现** (`xlog/logger.c`，~370 行)
   - **Timer 模式**：周期性定时器回调 flush 队列
   - **Notify 模式**：每条日志写入后通过 pipe 唤醒事件循环
   - **Mixed 模式**：定时器 + Error 级别以上走 pipe 紧急路径
   - **Fatal 同步路径**：直接格式化写入 + fflush + abort()
   - **文件轮转**：按 max_size 触发，级联重命名（path.{i-1} → path.{i}）
   - **同步 Flush**：pipe 触发 + 轮询等待队列清空
   - **xbase/log 桥接**：通过 `xLogSetCallback` 将 `xLog()` 重定向到 xlog

5. **单元测试** (`xlog/logger_test.cpp`，17 个测试)
   - 生命周期、级别过滤、三种模式、文件轮转、stderr 输出、多线程安全、桥接、时间戳格式、默认 flush 间隔、上下文宏

#### 宏改造：方案 A（上下文宏）

用户反馈每次调用宏都要传 `logger` 参数不优雅，采用方案 A 改造：

- 新增 `xLoggerCurrent()` 返回线程局部 logger（由 `xLoggerEnter` 设置）
- `XLOG_DEBUG/INFO/WARN/ERROR/FATAL` 改为无参版本，自动调用 `xLoggerCurrent()`
- 新增 `XLOG_*_L(logger, ...)` 显式版本，用于需要指定 logger 的场景
- 测试中原有宏调用改为 `_L` 版本，新增 `ContextMacrosUseCurrentLogger` 测试

## 经验总结

1. **清理路径必须唯一**：C 语言手动内存管理中，如果有多条路径都能触发清理，极易出现 double free。应该统一走一条路径，用标志位做幂等保护只是兜底。
2. **写测试能发现隐藏 bug**：`sse_parser_feed` 的 double free 是在写单测时才暴露的，说明 review 看代码不一定能发现所有问题，测试覆盖很重要。
3. **命名要精确**：`normal` 太泛化，`oneshot` 精确表达了"一次性请求-响应"的语义，和 `sse`（持续流）形成清晰对比。
4. **API 人体工学很重要**：宏每次都要传 `logger` 参数使用体验差，改为线程局部上下文 + 无参宏后调用更自然。同时保留 `_L` 显式版本兼顾灵活性。
5. **分支名要遵循规范**：项目要求 `<author>/<short-description>` 格式，不是 `feat/xxx`。提交前应先确认 STYLE.md 中的约定。
