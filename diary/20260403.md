## 今日工作

### PR #27 — SSE (Server-Sent Events) 客户端支持

PR 经过三轮 review + 修复后合并。

#### Review 过程

**第一轮 Review**：
- ✅ 肯定了 vtable 多态设计、SSE 解析器规范性、头文件重命名、API 设计
- 🐛 发现 `id` 字段 NUL 检查是死代码（`memchr(value, '\0', strlen(value))` 永远返回 NULL）
- ⚠️ 提出 cleanup 双路径风险、`cleaned` 标志位 code smell、清理契约不一致、内存分配失败处理、编译期保证缺失、缺少重连机制等问题

**第二轮 Review**：
- 大部分问题已修复，但发现两个遗留 bug：
  1. `destroy_req()` 走 vtable 路径后没有 `free(req)` → 内存泄漏
  2. `on_done` 直接调 `on_cleanup` 绕过 `cleaned` 标志位 → double free 风险

**第三轮 Review**：
- 清理流程基本理清，但 `sse_on_done` 里还残留了一行 `sse_on_cleanup(req_)` 调用

#### 代码修改

1. **修复 `sse_on_done` 中多余的 `sse_on_cleanup` 调用**
   - 删除直接调用，清理统一由 `check_multi_info` / `destroy_req` 负责
   - 避免 double free

2. **新增 SSE 单元测试** (`client_sse_test.cpp`)
   - 14 个测试用例，使用本地 `MiniSseServer`（极简 socket SSE 服务器）
   - 覆盖：参数校验、单/多事件接收、自定义事件类型、多行数据、事件 ID、注释行过滤、用户中断、on_done 回调、销毁时有 SSE 在飞、连接失败处理

3. **修复 `sse_parser_feed` 中的 double free**
   - 空行分支里 `free(line)` 后落到循环末尾又 `free(line)`
   - 写测试时发现的 bug

4. **重命名 `normal` → `oneshot`**
   - `normal_on_done` → `oneshot_on_done`
   - `normal_on_cleanup` → `oneshot_on_cleanup`
   - `normal_vtable` → `oneshot_vtable`
   - 语义更清晰：oneshot = 一发一收，sse = 持续推送

5. **本地 Linux 容器测试**
   - 使用 `scripts/test-linux.sh` 通过 Apple Containerization 在 gcc:14 容器中跑测试
   - 全部通过

## 经验总结

1. **清理路径必须唯一**：C 语言手动内存管理中，如果有多条路径都能触发清理，极易出现 double free。应该统一走一条路径，用标志位做幂等保护只是兜底。
2. **写测试能发现隐藏 bug**：`sse_parser_feed` 的 double free 是在写单测时才暴露的，说明 review 看代码不一定能发现所有问题，测试覆盖很重要。
3. **命名要精确**：`normal` 太泛化，`oneshot` 精确表达了"一次性请求-响应"的语义，和 `sse`（持续流）形成清晰对比。
