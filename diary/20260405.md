完成了 HTTP/2 路线图中 Step 1 的全部工作：将 `xHttpConn_` 中与 llhttp 强耦合的协议解析逻辑抽取到 `xHttpProto` vtable 接口后面，使连接管理层与具体协议实现解耦。

#### 方案讨论与设计决策

| # | 决策点 | 结论 |
| --- | -------- | ------ |
| 1 | `xHttpProtoH1` 分配方式 | 堆分配（`calloc`），不使用 union 内嵌 |

| 3 | `on_data` 返回值语义 | 三值返回：`0` = 继续等待，`1` = 请求完整，`-1` = 解析错误 |
| 4 | Response 写入路径 | 本阶段不动，留到 Step 3 引入 HTTP/2 时再抽象 |

#### 核心实现

**1. 定义 `xHttpProto` vtable 接口（`server_private.h`）**

```c
typedef struct xHttpProto_ {
  int          (*on_data)(struct xHttpConn_ *conn, const char *buf, size_t len);
  void         (*reset)(struct xHttpConn_ *conn);
  void         (*destroy)(struct xHttpConn_ *conn);
  const char  *(*method)(struct xHttpConn_ *conn);
  int          (*should_keep_alive)(struct xHttpConn_ *conn);
  void         *state;
} xHttpProto;
```

用 `xHttpProto proto` 字段替换了 `xHttpConn_` 中原有的 `llhttp_t parser` 和 `llhttp_settings_t parser_settings`，`server_private.h` 不再 `#include <llhttp.h>`。

**2. 实现独立的 HTTP/1.1 协议处理器（`proto_h1.c`）**

新建 `proto_h1.c` 和 `proto_h1.h`，包含：

- `xHttpProtoH1` 结构体（内含 `llhttp_t parser` + `llhttp_settings_t settings`）
- 从 `server.c` 搬迁的 6 个 llhttp 回调函数（`on_url`、`on_header_field`、`on_header_value`、`on_headers_complete`、`on_body`、`on_message_complete`）
- 5 个 vtable 方法实现（`h1_on_data`、`h1_reset`、`h1_destroy`、`h1_method`、`h1_should_keep_alive`）
- `xHttpProtoH1Init()` 初始化函数：堆分配 + 回调绑定 + vtable 填充

**3. 改造 `server.c` 调用点**

将 5 个 llhttp 直接调用点全部替换为 vtable 调用：

| 调用点 | Before | After |
| -------- | -------- | ------- |
| 初始化 | `llhttp_init()` + 手动设置回调 | `xHttpProtoH1Init(conn)` |
| 数据解析 | `llhttp_execute()` + 分别检查 error/complete | `conn->proto.on_data()` 三值返回 |
| 获取方法 | `llhttp_method_name(conn->parser.method)` | `conn->proto.method(conn)` |
| 重置 | `llhttp_reset(&conn->parser)` | `conn->proto.reset(conn)` |
| 销毁 | 无 | `conn->proto.destroy(conn)` |

删除了 `server.c` 中的 6 个 llhttp 回调函数定义和 forward declarations，`server.c` 不再包含 `#include <llhttp.h>`。

#### 架构变化

```text
Before:  xHttpConn_ ──直接嵌入──> llhttp_t + llhttp_settings_t
After:   xHttpConn_ ──vtable──> xHttpProto ──state──> xHttpProtoH1 (堆分配)
                                                        └── llhttp_t + llhttp_settings_t
```

## 经验总结（协议抽象层）

1. **vtable 抽象的粒度要恰到好处**：`xHttpProto` 只暴露了 5 个方法（`on_data`、`reset`、`destroy`、`method`、`should_keep_alive`），刚好覆盖 `server.c` 中所有与协议相关的操作。请求解析状态（`url`、`headers_raw`、`body` 等）保留在 `xHttpConn_` 中，因为这些是 HTTP/1.1 和 HTTP/2 共有的通用属性。
2. **三值返回简化了调用方逻辑**：原来 `on_conn_event` 中需要分别检查 `llhttp_execute` 的返回值、`pending_error` 标志和 `request_complete` 标志，改为 `on_data` 内部封装后只需判断 `rc < 0 / rc > 0 / rc == 0`，代码更清晰。
3. **独立文件有利于后续扩展**：将 llhttp 回调放在独立的 `proto_h1.c` 中，未来添加 `proto_h2.c` 时只需实现相同的 vtable 接口，`server.c` 无需任何改动。

### xhttp 测试文件拆分

将原 `server_test.cpp`（1353 行）拆分为 3 个文件，提升可维护性和可读性。

#### 拆分方案

| 文件 | 内容 | 测试数 |
| ------ | ------ | -------- |
| `server_test_helper.h` | 公共 helpers（`pump_loop`、`find_free_port`、`connect_to`、`send_str`、`recv_all`）、共享结构体（`HandlerCtx`、`ParamHandlerCtx`）、`HttpServerTest` fixture | — |

CMakeLists.txt 使用 `file(GLOB_RECURSE "*_test.cpp")` 自动收集测试文件，拆分后无需修改构建配置。

#### CMakeLists.txt 修复

发现 `file(GLOB_RECURSE XHTTP_HEADERS "*.h")` 会将 `server_test_helper.h` 收集进 `libxhttp` 的构建源文件列表。虽然不影响编译产物，但不够干净。添加了一行过滤：

```cmake
list(FILTER XHTTP_HEADERS EXCLUDE REGEX "_test")
```

将文件名中包含 `_test` 的头文件从库的构建列表中排除。

#### 拆分验证结果

- 编译：零警告零错误
- 测试：66 个测试全部通过（ASAN 模式无内存问题）
- 原 `server_test.cpp` 已删除

| ------ | --------- |

| `xhttp/server_test_helper.h` | 新建，公共测试辅助头文件 |
| `xhttp/server_h1_test.cpp` | 新建，HTTP/1.1 测试（63 个） |

## 经验总结（测试拆分）

1. **GLOB_RECURSE 的副作用**：使用 `file(GLOB_RECURSE "*.h")` 收集头文件时，测试辅助头文件也会被收进库的源文件列表。用 `list(FILTER ... EXCLUDE REGEX ...)` 可以干净地过滤掉不需要的文件。
2. **测试文件拆分原则**：按协议版本（H1/H2）拆分测试文件，公共 helpers 提取到独立头文件中，既保持了测试的独立性，又避免了代码重复。

### CI 流水线修复与 PR 合入

#### 问题 1：CI 缺少 nghttp2 依赖

**现象**：PR 创建后 CI 流水线失败，CMake configure 阶段报 `find_package(Nghttp2 REQUIRED)` 找不到 nghttp2。

**根因**：`.github/workflows/ci.yml` 的依赖安装步骤没有安装 nghttp2，这是新增 HTTP/2 支持后遗漏的。

**修复**：

- Ubuntu：`apt-get install` 增加 `libnghttp2-dev`
- macOS：`brew install` 增加 `nghttp2`

#### 问题 2：PR 合并冲突

**现象**：PR 显示与 main 分支有冲突，涉及 6 个文件。

**根因**：main 分支上有旧的仅 HTTP/1.1 版本代码，和功能分支新增的 HTTP/2 支持产生冲突。

**修复**：`git merge main` 后全部采用 `--ours`（保留 H2 版本），涉及 `docs/xhttp/README.md`、`docs/xhttp/server.md`、`xhttp/CMakeLists.txt`、`xhttp/TODO.md`、`xhttp/server.c`、`xhttp/server_private.h`。

#### 问题 3：duplicate symbol 链接错误（175 个）

**现象**：CI 再次失败，macOS clang 链接阶段报 175 个 duplicate symbol 错误。

**根因**：拆分测试文件时，旧的 `server_test.cpp` 没有删除。CMakeLists.txt 用 `file(GLOB_RECURSE "*_test.cpp")` 匹配所有测试文件，导致 `server_test.cpp`（35 个测试）和 `server_h1_test.cpp`（35 个完全相同的测试）同时被编译链接，产生重复符号。

**修复**：`git rm xhttp/server_test.cpp`，只保留拆分后的 `server_h1_test.cpp` 和 `server_h2_test.cpp`。

#### 最终结果

CI 通过，PR #45 合入 main ✅

1. **新增外部依赖时别忘了 CI**：添加 nghttp2 依赖后，本地开发环境已安装所以测试通过，但 CI 环境是干净的，必须同步更新 CI 配置。
