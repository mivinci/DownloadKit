## 今日工作

### 1. PR #60 Review 处理：goto-fail 错误清理重构

**问题现象**：mivinci 在 PR #60 的 `xnet/transport_openssl.c` 第 284 行留了 review comment——"这个函数里的错误处理是不是能用 goto 优化"。

**排查过程**：

- 分析了 `xTransportTlsClientInit` 函数，发现每个错误分支都手动重复释放 `SSL_CTX_free(ctx)` / `SSL_free(ssl)` / `SSL_CTX_free(ctx)` 等资源，随着资源层级增多，清理代码越来越冗长且容易遗漏。
- 全项目搜索了同类问题，发现 OpenSSL 相关的 4 个函数都有此问题，而 mbedTLS 对应的函数已经在用 `goto fail` 模式。

**根因分析**：初始实现时每个错误分支独立处理清理逻辑，没有统一使用项目 STYLE.md §6.4 规定的 `goto fail` 模式。

**修复方案**：对以下 4 个函数统一重构为 `goto fail` / `goto fail_ssl` 两级标签清理模式：

| 文件 | 函数 |
| ---- | ---- |
| `xnet/transport_openssl.c` | `xTlsCtxCreate` |
| `xnet/transport_openssl.c` | `xTransportTlsClientInit` |
| `xhttp/transport_tls_server_openssl.c` | `xHttpTlsCtxCreateOpenSSL` |
| `xhttp/transport_tls_client_openssl.c` | `xHttpTlsClientTransportInit` |

对于 Client Init 类函数，因为有两级资源（`SSL_CTX` 和 `SSL`），使用了两级标签：

```c
fail_ssl:
  SSL_free(ssl);
fail:
  if (ctx) SSL_CTX_free(ctx);
  return -1;
```

**不需要改的文件**：

- mbedTLS 系列已经在用 `goto fail` ✅
- `tcp_listener.c` 每个错误分支清理行为不同，不适用统一 goto 模式 ✅

### 3. xhttp WS Client TLS 改造：共享 xTlsCtx

**问题现象**：WebSocket 客户端（`ws_connect.c`）的 TLS transport 存在与 TCP 客户端相同的性能问题——每个 wss:// 连接都创建独立的 `SSL_CTX`（OpenSSL）或完整的 `mbedtls_ssl_config` + 熵源 + CA 证书链（mbedTLS），导致重复磁盘 I/O、无法复用 TLS 会话。

**排查过程**：

- 分析 `transport_tls_client_openssl.c`（238行）和 `transport_tls_client_mbedtls.c`（436行），发现与 xnet 的 transport 代码高度重复
- 确认 HTTP Server 已使用共享 `xTlsCtx`，HTTP Client 走 libcurl 无需改动
- 仅 WS Client 需要改造

**修复方案**：

1. `ws.h` — `xWsConnectConf` 新增 `tls_ctx` 字段（优先级高于 `tls`）
2. `transport_tls_client.h` — `xHttpTlsClientTransportInit` 签名改为接受 `xTlsCtx`
3. `transport_tls_client_openssl.c` — 移除 per-connection `SSL_CTX` 创建，改用 `xTlsCtxGetNative()` 获取共享 ctx
4. `transport_tls_client_mbedtls.c` — 移除 per-connection config/entropy/cert 加载，改用共享 ctx
5. `ws_connect.c` — 添加 tls_ctx 解析逻辑（tls_ctx > tls conf > defaults），管理 ownership

**结果**：净减少 ~190 行重复 TLS 设置代码，全部 5 个测试套件通过。

## 经验总结

1. **goto-fail 是 C 语言错误处理的标准模式**：Linux 内核、OpenSSL 源码都大量使用。项目 STYLE.md §6.4 已有明确规范，新代码应从一开始就遵循。
2. **新增功能后要全项目检查一致性**：这次 review 暴露的问题不仅存在于被评论的函数，xhttp 下的 OpenSSL 文件也有同样问题。修复时应一并处理，避免留下技术债。
3. **两级标签适用于多层资源分配**：当函数中有 A → B → C 的资源分配链时，用 `fail_c` / `fail_b` / `fail` 多级标签比单一 `fail` 更精确，避免释放未初始化的指针。
4. xhttp 的 `xHttpTransport` 和 xnet 的 `xTransport` vtable 结构完全一致（read/writev/handshake/alpn/destroy），但枚举值名不同（`xHttpTransportResult_*` vs `xTransportResult_*`），未来可考虑统一
5. WS Client 的 TLS transport 改造模式与 TCP Client 完全一致：共享 ctx + per-connection SSL object + SNI/hostname 设置
6. `xTlsCtxGetNative()` 作为内部 API 被 xhttp 模块通过 `extern` 声明使用，后续可考虑将其放入公共内部头文件
