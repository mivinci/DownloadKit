## 今日工作

### 1. xhttp WS Client TLS 改造：共享 xTlsCtx

**问题现象**：WebSocket 客户端（`ws_connect.c`）的 TLS transport 存在与 TCP 客户端相同的性能问题——每个 wss:// 连接都创建独立的 `SSL_CTX`（OpenSSL）或完整的 `mbedtls_ssl_config` + 熵源 + CA 证书链（mbedTLS），导致重复磁盘 I/O、无法复用 TLS 会话。

**排查过程**：

- 分析 `transport_tls_client_openssl.c`（238行）和 `transport_tls_client_mbedtls.c`（436行），发现与 xnet 的 transport 代码高度重复
- 确认 HTTP Server 已使用共享 `xTlsCtx`，HTTP Client 走 libcurl 无需改动
- 仅 WS Client 需要改造

**修复方案**：

1. `ws.h` — `xWsConnectConf` 新增 `tls_ctx` 字段（优先级高于 `tls`）
2. `transport_tls_client.h` — `xHttpTlsClientTransportInit` 签名改为接受 `xTlsCtx`
3. `transport_tls_client_openssl.c` — 移除 per-connection `SSL_CTX` 创建，改用 `xTlsCtxGetNative()` 获取共享 ctx
4. `transport_tls_client_mbedtls.c` — 移除 per-connection config/entropy/cert 加载，改用共享 ctx
5. `ws_connect.c` — 添加 tls_ctx 解析逻辑（tls_ctx > tls conf > defaults），管理 ownership

**结果**：净减少 ~190 行重复 TLS 设置代码，全部 5 个测试套件通过。

### 5. CI 流水线修复

**问题现象**：PR #62 的 4 个 Build & Test job 全部失败。

**排查过程**：

- macOS/ubuntu × openssl/mbedtls 四个 job 均报 `xTlsCtxIsServer` 未声明（`xnet/transport_test.cpp:174`）
- mbedTLS 的两个 job 额外报 `MBEDTLS_ERR_NET_SEND_FAILED` / `MBEDTLS_ERR_NET_RECV_FAILED` 未声明（`xhttp/transport_tls_client_mbedtls.c:57,73`）

**根因分析**：

- `transport_test.cpp` 的 `extern "C"` 块只 include 了 `transport_private.h`，而 `xTlsCtxIsServer` 声明在 `tls_private.h` 中
- `transport_tls_client_mbedtls.c` 缺少 `<mbedtls/net_sockets.h>` 头文件（同模块的 `transport_tls_server_mbedtls.c` 和 xnet 的 `transport_mbedtls.c` 都有 include）

**修复方案**：

- `xnet/transport_test.cpp` — 在 `extern "C"` 块中添加 `#include "tls_private.h"`
- `xhttp/transport_tls_client_mbedtls.c` — 添加 `#include <mbedtls/net_sockets.h>`

**结果**：修复推送后 PR #62 CI 通过，已合入 main。

## 经验总结

- xhttp 的 `xHttpTransport` 和 xnet 的 `xTransport` vtable 结构完全一致（read/writev/handshake/alpn/destroy），但枚举值名不同，未来可考虑统一
- `xTlsCtxGetNative()` 作为内部 API 被 xhttp 模块通过 `extern` 声明使用，后续可考虑将其放入公共内部头文件
- 移除 libcurl 的推荐路径是先让 curl 变为可选依赖（内置轻量 H1 Client），而非一步到位完全移除
