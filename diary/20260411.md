#### 1c. CI 修复：GCC sign-compare 警告

**问题现象**：Ubuntu GCC 编译 `datachannel.c` 报 `-Werror=sign-compare` 错误。

**根因**：`datachannel.c:149` 中 `12 + label_len + proto_len > len`，左侧 `int` 字面量 + `uint16_t` 被提升为 `int`（有符号），与右侧 `size_t`（无符号）比较。macOS clang 默认不报此警告。

**修复**：将 `12` 显式转为 `(size_t)12`。

#### 1d. CI 修复：mbedTLS 2.x sha256 API 兼容性

**问题现象**：Ubuntu 上 mbedTLS 2.x 的 `mbedtls_sha256` 被标记为 deprecated（返回 void），代码中 `return mbedtls_sha256(...)` 触发 `-Werror=deprecated-declarations` 和 `void value not ignored` 错误。

**修复**：细化版本判断——2.x 用 `mbedtls_sha256_ret`，3.x 用 `mbedtls_sha256`，4.x 用 PSA API。

#### 1e. mbedTLS DTLS 握手递归问题修复

**问题现象**：mbedTLS 后端的 DTLS 握手测试全部失败，双方卡在 Connecting 状态。

**排查过程**：

1. 添加 fprintf 调试日志，发现 `drive_handshake` 被无限递归调用
2. 分析递归路径：mbedTLS 的 `mbedtls_ssl_handshake` 在执行过程中同步调用 send callback → 对方 `FeedInput` → 对方 `drive_handshake` → 对方 `handshake` → 对方 send callback → 当前 `FeedInput` → 递归
3. 第一版修复（`driving` 标志阻止递归）导致 OpenSSL 后端也失败——因为 OpenSSL 的 `flush_bio_out` 也在 `handshake()` 内部调用 send callback
4. 分析 OpenSSL 失败原因：Passive 的 `flush_bio_out` 触发 Active 处理并回传数据，但 Passive 的 `driving=true` 阻止了后续处理，`SSL_do_handshake` 第二次调用时返回 `SSL_ERROR_SYSCALL`

**根因**：两个后端的发送机制不同——mbedTLS 在 `handshake()` 内部内联发送，OpenSSL 在 `handshake()` 内部通过 `flush_bio_out` 发送。两者都会在 loopback 场景下触发递归。

**最终修复方案**（三层修改）：

1. **`dtls_backend.h`**：新增可选的 `flush_output` 接口，将 OpenSSL 的 flush 从 `handshake()` 中分离
2. **`dtls_openssl.c`**：`openssl_handshake` 不再调用 `flush_bio_out`（握手完成时除外），新增 `openssl_flush_output` 方法
3. **`dtls_transport.c`**：
   - 添加 `driving` + `feed_while_driving` 双标志
   - `drive_handshake` 中：设置 `driving=true` 防止递归；`handshake()` 返回后调用 `flush_output()`（在 driving 保护下）；`Again` 时检查 `feed_while_driving` 决定是否继续循环
   - `FeedInput` 中：`driving=true` 时只写入数据并设置 `feed_while_driving=true`，不调用 `drive_handshake`
4. **`dtls_mbedtls.c`**：`.flush_output = NULL`（内联发送，无需 flush）

**验证**：OpenSSL 156/156 通过，mbedTLS 156/156 通过。

## 经验总结

1. **TLS 后端的 I/O 模型差异需要在 transport 层抽象**：OpenSSL 用 memory BIO 缓冲输出需要显式 flush，mbedTLS 通过回调内联发送。将 flush 从 handshake 中分离为独立接口是解决递归问题的关键
2. **loopback 测试中同步 send callback 会触发递归**：需要 re-entrancy guard（`driving` 标志）+ 延迟驱动（`feed_while_driving` 标志）来打破递归链
3. **CI 跨平台编译差异要注意**：GCC 比 clang 更严格（`-Wsign-compare`），不同版本的 mbedTLS API 签名不同（2.x `void` vs 3.x `int`），本地通过不代表 CI 通过
